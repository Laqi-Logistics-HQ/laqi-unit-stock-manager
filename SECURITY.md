# Security policy

Thank you for taking the time to report a problem responsibly. This plugin runs
on live shops, so a quiet report and a fast release protect merchants far better
than a public one.

## Supported versions

| Version | Supported |
|---------|-----------|
| Latest release | Yes |
| Anything older | No, update first |

Fixes ship in a new release to the WordPress.org plugin directory. There are no
backports to earlier versions. If you are reporting against an older release,
please check the latest one first where you can.

The Pro add-on is a separate product in its own repository. Report issues in it
to the same address and say which edition you mean.

## Reporting a vulnerability

Use either route. Both are private and both reach the same person.

- **GitHub**, through the Security tab of this repository:
  [report a vulnerability](https://github.com/Laqi-Logistics-HQ/laqi-unit-stock-manager/security/advisories/new).
  That opens a draft advisory only we can see, and keeps the report, the
  discussion and the fix together in one place.
- **Email** **support@laqi-logistics.com** with `Security` in the subject line,
  if you would rather not use GitHub or do not have an account.

Please do not open an ordinary GitHub issue, and do not post in the WordPress.org
support forum. Both are public, and an unpatched report in either puts every
install at risk before a fix exists.

Useful things to include, as far as you have them:

- Plugin version, and whether it is the free or the Pro edition.
- WordPress, WooCommerce, and PHP versions.
- Steps to reproduce, or a proof of concept.
- The lowest user role that can trigger it, for example subscriber, customer, or
  shop manager.
- What an attacker gains: data read, data written, code executed, stock altered.

## What happens next

- We acknowledge your report within 5 working days.
- For a confirmed issue we aim to release a fix within 30 days, sooner when it is
  serious and straightforward.
- We will credit you in the changelog if you want that. Tell us the name or handle
  to use, or say you would rather stay anonymous.
- There is no bug bounty. This is a small operation and nothing is paid.

## Disclosure

Please hold public details until a fixed version has been available for 7 days,
or 90 days after your report, whichever comes first. We will tell you when the
release is out.

WordPress.org may close a plugin's listing while a fix is being prepared. That is
their normal process, not a sign the report was mishandled.

## If we do not respond

Escalate to the WordPress.org Plugin Directory security team at
**plugins@wordpress.org**. They ask reporters to contact the developer first,
which is exactly why this file exists, so a stalled report is a fair reason to go
to them.

## Scope

In scope: the code in this repository, as shipped in the WordPress.org release.

Out of scope, because they are not ours to fix or not a vulnerability:

- WordPress core, WooCommerce, and any other plugin or theme.
- Anything that needs an administrator account to exploit. Administrators can
  already run code on their own site.
- Volumetric denial of service, or load generated by ordinary plugin use.
- The configuration of a site we do not control, including its server headers,
  file permissions, and TLS setup.
